# 待办清单（TodoList）模块 — Harness 演示用 PRD

## 1. 目标
实现一个待办清单（TodoList）模块，演示 Harness 端到端能力：
Planner 拆解 → Coder 多文件生成 → Reviewer 审查 → 编译验证 → 经验沉淀。

## 2. 数据结构
Todo 接口（字段名严格匹配）:
- id: string                （唯一标识）
- title: string             （标题，1-50 字符）
- description: string       （详情，可选，最多 500 字符）
- done: boolean             （是否完成）
- level: 'low' | 'mid' | 'high'  （优先级）
- deadline: string | null   （截止日期，ISO 字符串）
- createdTime: string       （创建时间，ISO 字符串）

## 3. 需要生成的文件
- src/types/index.ts：追加 Todo 接口和 Level 联合类型
- src/api/todoService.ts：CRUD 方法（list/get/create/update/remove/toggleDone）
  - 所有方法必须返回 Promise<Todo> 或 Promise<Todo[]>
- src/hooks/useTodoList.ts：自定义 Hook
  - 返回值必须包含 list/loading/refresh/remove/toggleDone
  - 内部 await 后必须用 try/catch
- src/pages/TodoList/index.tsx：列表页
  - 使用 antd 的 List/Tag/Switch/Modal.confirm
  - level 用不同颜色 Tag 展示
  - done 用 Switch 切换
  - 删除前用 Modal.confirm 确认
  - 操作反馈用 message.success / message.error

## 4. 强约束（违反会导致编译失败）
1. 所有时间字段用 ISO string，不用 Date 对象
2. 所有 async 函数必须返回 Promise<T>，不能直接返回 T
3. Hook 必须返回 loading 状态
4. 必须保留 src/types/index.ts 中已定义的字段，不要删除或注释
5. 字段名严格按第 2 节，不要改成 completed/priority/dueDate 等

## 5. 演示前置条件
跑这个 PRD 前建议先做：
1. 跑过一次后 Harness 会沉淀经验到 memory/lessons-*.md
2. 第二次跑同类需求时，Planner 会自动加载这些经验（关键词匹配）
3. 观察 trace/trace-*.md 报告可以看完整的 Agent 执行链路

## 6. 验收标准
- `npm run build` 成功，0 个 TypeScript 错误
- 列表页能展示 todos，支持切换完成状态和删除
- 所有组件遵循三层架构（Page → Hook → Service）
