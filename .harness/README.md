# Harness 项目规则说明（人读版）

## 🚀 在新项目中接入 harness

> 把 `.harness/` 整个目录拷到目标项目根，然后跑三条命令。

```bash
# 1) 探测项目现状并生成 rules.yaml（默认会探测 tsconfig.json paths /
#    package.json 框架 / src/ 顶层目录 / 命名风格，分歧抛 conflict 让你拍板）
.harness/commands/harness init               # 交互式
.harness/commands/harness init --dry-run     # 只看 plan 不写盘
.harness/commands/harness init --yes         # 所有 conflict 走默认，不交互
.harness/commands/harness init --json        # CI / 程序消费用

# 2) 把 harness 接到 Agent（注册 PostToolUse hook + CLAUDE.md 引用）
.harness/commands/harness install --agent claude   # 或 ducc / baidu-cc

# 3) 全量扫一次，生成 .harness/generated/claude.md
.harness/commands/harness scan
```

`init` 是三段式（probe → resolve → apply）：

| 阶段 | 干什么 | 产出 |
|------|--------|------|
| probe   | 只读扫一遍项目根：tsconfig.json / package.json / src/ / .eslintrc / .gitignore | `ProbeReport` |
| resolve | 对照出厂默认 `rules.yaml`，自动采纳能采纳的，分歧抛 `Conflict` 让用户选 | `ProposedPlan` |
| apply   | 把用户答复（或 `--yes` 走 `default_choice`）落到 rules.yaml + 必要目录 | 写盘 |

**自动采纳的**（不打扰用户）：
- tsconfig.json `paths` 别名（采纳探测值，与默认一致时静默沿用）
- layer 路径与默认不同时直接采纳现状（例：默认 `component.paths=[src/pages/, src/components/]`，但项目只有 `src/components/` → 采纳）
- 探测到的框架 / 包管理器（只打 info note，不进 rules）

**抛 conflict 让用户拍板的**：
- `src/` 下未识别的目录（例 `src/utils/`）：映射到某 layer / 加进 `exclude_dirs` / 先放着
- 命名风格背离默认（样本 ≥ 3 且实际命中率 < 50%）：保留默认 / 采纳现状风格 / 不校验该层

**不会自动猜的**：
- `imports.forbidden_imports` / `imports.rewrites` —— 业务语义无法探测，需要手写

接入后建议看 [`.harness/docs/presets.md`](docs/presets.md) 对照常见项目形态调整。

## 🔥 团队经验教训（节选）

### [warning] 批量删除应区分三态并并发执行

- 适用: `src/pages/, src/components/, src/hooks/`
- 关键词: batch, delete, Promise.allSettled, Popconfirm, 批量

批量删除/批量操作必须：1) UI 加 Popconfirm 二次确认；2) 用 Promise.allSettled 并发，不要串行 await；3) 区分全成功/部分失败/全失败三态，部分失败时要告诉用户哪几条没删掉。

### [info] 状态管理优先用 useState 而非 useReducer

- 适用: `src/components/, src/hooks/`
- 关键词: state, useState, useReducer

对于 <5 个字段的本地状态，useState 更直观。useReducer 留给跨字段联动。

> 增删经验：`harness lesson add` / `harness lesson remove <id>`
> 经验存放在：`.harness/memory/lessons/`
